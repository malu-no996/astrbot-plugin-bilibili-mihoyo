## 修「群订阅页看不到数据」（两个真因 + 一个环境因素）

用户反馈：「已经有一个群订阅了，但『订阅的群』页面看不到新数据」。

排查证据（`C:\Users\Administrator\.astrbot\data`）：
- `zzz/subscribe.json` 内容 `{"services": {}}`，但 mtime = 00:24:47，
  与日志 `已订阅米哈游服务 ✅`（00:24:47）同秒 —— **订阅流程跑了、写盘也调了，写进去的却是空表**。
- 00:24:47 那条回复文案是「到面板『米哈游功能命令 → QQ机器人配置』…」＝**旧文案**，
  新版应是「『群订阅 → 订阅的群』…」→ 说明**线上进程跑的还是旧代码**（23:42 那次重载加载的是改动前的版本）。

### 真因 1（服务端）：空容器被 `or {}` 换成了临时对象
`miyoho/social/subscribe.py` 里 4 处写入点写的是
`services = _get().get("services") or {}` —— 当 services 是**空 dict**（falsy）时，
`or {}` 返回一个**新的临时 dict**，`setdefault` / 赋值全落在这个临时对象上，
`_save(_get())` 存回去的仍是原来那个空表。现象：命令回成功、文件 mtime 更新、内容还是空。
→ 只要 subscribe.json 是空表，「首次订阅」必然写不进去（23:26 被面板清空后，00:24 就中招了）。
修复：4 处全改成 `_get().setdefault("services", {})`（取**真实**容器）：
`set_group_enabled` / `drop_group` / `handle_sub` / `handle_unsub`。
（99/105/113 行是**只读**兜底，`or {}` 无副作用，保留。）

### 真因 2（前端）：v-if / v-else-if 串成一条链，群卡片恒被吃掉
`pages/panel/index.html` 里「机器人一览」`gs-bots` 用 `v-if`、「订阅的群」`gs-list` 用 `v-else-if`
—— 二者互斥。而 `_bot_meta()` **必然**返回在线实例 + social.json 里出现过的实例
（一定非空）→ `gs-list` 永远不渲染。用户看到的就是「有机器人 chip、但一个订阅的群都没有」。
修复：`gs-list` 改成独立的 `v-if`（`<p v-else-if="mys.sub.done">` 仍与它配对）。

### 环境因素：静态页 vs 后端路由的重载口径不同
- `pages/panel/*` 是**静态文件**，刷新页面就加载新前端（不依赖插件重载）→ 所以用户能看到新页签。
- 但 `subscribe_routes.py` 的新路由要**插件重载**才注册，否则前端请求 404（页面只显示 error 文案）。
→ 改完必须：`cp` 到线上目录 + 在 WebUI 重载插件。

  否则「只发过订阅、没发别的」的群在「群员绑定」页里一个人都看不到。
